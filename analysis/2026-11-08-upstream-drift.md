**Retain the current pins and manual/adapter routes.** This comparison accounts for released upstream sources and the maintainer host’s installed commands. Source inspection does not qualify runtime discovery, permission enforcement or embedded execution.

Why: the monthly comparison is due, and upstream releases, retired commands, invocation policies and dependency closure have changed. The next comparison is due **2026-12-08**, or before a release changes an upstream contract.

## Results that affect adoption

1. gstack now has authoritative tagged releases. The current stable release observed is v1.98.0.0, not October's untagged 1.91.54.0 snapshot. Its standalone `plan-eng-review` is retired even though its methodology remains in source for autoplan; `investigate` is deleted and retired. Current pins keep the old contracts, so this is an upgrade hazard rather than proof that pinned consumers already fail.
2. All eight embedded integration keys remain blocked. The exact-source checker produced 22 distinct decisions (each reproduced in final validation): **8 incompatible, 14 drifted, all exit 2, all may_invoke=false**. No manifest or digest was changed to admit anything.
3. gstack Claude frontmatter makes `land-and-deploy` user-only, unlike the registry's model ownership; the Codex metadata generator still emits implicit invocation=true. Both surfaces must be reconciled in an adoption proposal.
4. Matt v1.3.2 changes tracker/setup writes, review context isolation, ticket edges, mutation proof, Wayfinder branch publication and a conditional design reference. Several commands are byte-identical, but not every dependency directory is.
5. pstack remains a source-only dependency without a published release/tag in its repository feed. Its latest path snapshot changes verification-harness usable-readiness and stand-in coverage requirements. Keep the five local adapters and current provenance pin.
6. Official host docs confirm discovery and permission differences worth a separate host qualification. In particular, Codex now documents `untrusted` approval policy as retired. No model availability, performance or default was investigated or adopted.
