# Matt skills migration — acceptance contract

1. Fresh full and lite projects use GLOSSARY.md. Live guidance consistently
   identifies domain vocabulary there; historical evidence stays historical.
2. Existing managed CONTEXT.md projects can migrate content, pristine base and
   provenance together. Domain definitions and unrelated state/configuration are
   preserved. Retries after interruption are recoverable and successful reruns
   make no changes. Missing/edited bases, collisions, symlinks and user-owned
   maps or wider-context content require explicit review rather than replacement.
   The documented manual path covers mapped projects and preserves their links.
3. A failed domain migration prevents the ordinary upgrader from certifying the
   project or creating an empty replacement glossary. Review output names the
   affected files. Old names retain delivery-policy protection; new names and
   nested glossaries receive the same protection.
4. Matt is pinned to v1.3.1, commit 24fe0ef7737efae15c87225755e9f6f5965e4888.
   Installation guidance resolves that tag explicitly. Removed conflict-skill
   metadata remains available for migration, but no live route requires it.
5. Stage-owned conflict resolution preserves intent and verification. PR and
   environment-retro practices retain attribution, stage authority and existing
   gstack retro naming. New orchestration remains optional future work.
6. Exact inspected reviewer source digests and evidence advance without granting
   embedded permission. Host-install qualification dates are not invented.
7. Focused regression tests, independent review, privacy checks, generated
   inventories/manifests and canonical playbook verification pass before shipment.

Manual migration is deliberately required for project-authored maps and ambiguous
content: the upgrader cannot infer the intended domain boundaries from prose.
This narrows automation while covering those projects through a reviewable path.
