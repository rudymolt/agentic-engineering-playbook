# Consumer workflow reliability — contract

1. Start substantive ordinary slices at an adjustable estimate of 250 aggregate
   tool calls, broad final verification at a separate 300 calls, and multi-slice
   work at a 300-minute forecast. Scale down for small work. These are neither
   ceilings nor minimum consumption targets. Aggregate observable worker and
   coordinator usage once; report unavailable counters without inventing them.
2. At checkpoints report completed and independently verified work, remaining
   work, changed evidence and revised calls/time forecasts. Productive authorized
   work continues. Owner-selected hard caps, actual quotas, Stop, cumulative
   three-failure/no-progress guards, protected ceilings and build scope bind.
3. Bootstrap/upgrade review distinguishes inherited estimates, explicitly
   retained caps and ambiguous legacy prose. Preview is read-only. Preserve
   customizations and use existing three-way merge/manual adoption boundaries.
   Unresolved conflict retains prior certification. Reviewed conversion and
   deliberate retention must both replay without changes.
4. Diagnose the startup gap using exact release/inventory, effective setup,
   whole-command receipt, workspace history, initial host catalog and permitted
   invocation. A historical evidence gap is reported as such. Repair only a
   reproduced seam, with regression and preservation evidence.
5. Qualify the selected 20 upstream skills on Claude Code and Codex separately:
   dependencies/support files/notices, discovery before repair and permitted
   explicit invocation. Unsupported embedded reviewers use their documented
   fallback. Missing evidence remains incomplete. No claim of unrestricted
   skill side effects or unsupported native dispatch follows from source loading.
6. Verify fresh creation/session restart/recreation, idempotent replay, retained
   customization, partial failure and journal recovery. Keep prior evidence's
   exact scope; no unperformed VM restart claim.
7. Require fresh independent review, generated manifests, the full final-candidate
   verifier, required CI and reviewed release before deliberate consumer adoption.
   Monthly upstream/runtime/model/settings review is due before release. Preserve
   approved pins and customizations unless a separately reviewed change adopts
   them; setup never updates them automatically.

No second policy engine or speculative provisioning framework is requested.
