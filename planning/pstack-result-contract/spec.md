# Acceptance contract

1. Every exit from the five adaptations emits YAML `playbook_result` with
   `outcome` (complete, blocked or handoff), concrete `next_stage` (stage id,
   /whats-next or null), and ordered `required_actions`.
2. Why/how can complete a bounded qualified answer with unknowns; completing an
   explanation cannot certify a review gate. Missing essential prerequisites
   remain blocked. Stage-invoked answers return to their caller.
3. Blast-radius preserves acceptance blocks for essential unproven assumptions
   or defects and returns review ownership to stage 08.
4. Harness generation distinguishes proved, draft awaiting independent proof,
   and blocked work. Maintenance retains clean/changed/blocked as its audit
   finding; only complete accepted coverage can be offered to the stage owner
   for a timestamp. A report or envelope never writes state or permits shipping.
5. Scope both future ideas, investigation questions, compatibility constraints,
   evaluation criteria and update/customization strategy in an indexed Markdown
   file. Create one Linear backlog idea explicitly for further exploration,
   with no build-ready status, automatic agent delegation or implementation grant.
6. Preserve source attribution and metadata. Focused metadata, Markdown, links,
   privacy and generated-file checks pass; fresh scenario review checks routing
   across the five skills. Final shipping still requires the canonical verifier.
