# Pinned gstack provisioning — build contract

## Acceptance

- Bind the current registry gstack commit/version, complete source tree, lockfile,
  generator runtime and selected host output to a reviewed integrity record.
- Keep complete source and build dependencies outside recursive discovery roots.
  Publish only the selected host endpoints. Preserve the browser-name exception,
  the upgrade name and the Codex wrapper exclusion.
- Acquire only exact pinned inputs. Build with the frozen dependency lock and
  bounded commands; a failure never falls back to an unlocked install or latest.
- Preserve unknown directories, links, settings and customizations. Inventory
  validation replaces marker trust; missing managed support files are repairable,
  while unknown edits remain explicit conflicts.
- Report Codex safety-hook enforcement as unsupported; do not publish body text
  that falsely claims active enforcement. Preserve host-native fallback controls.
- Reuse release proof, adoption, reporting and transaction/recovery conventions.
  A complete package never certifies runtime discovery or behavior.
- Verify offline replay with a complete warm cache, interrupted acquisition/build,
  damaged inputs, wrong identity and conflicting endpoints in disposable Linux.

## Implementation notes

The full upstream tree includes runtime source, reference material and native
build inputs. Bind a source archive and generated host inventory to the adopted
release instead of executing stock setup. The source archive must be verified
before extraction or execution. Retain original bytes and source identities;
host adapters must be separately identified and invalidate embedded compatibility
where they change reviewed content. Keep runtime prerequisites separately pinned
and qualified. No unrelated global setup hooks or font installation is needed.

Monthly upstream/host review and deliberate compatibility migration preserve
customizations. A changed package or runtime invalidates affected qualification.
