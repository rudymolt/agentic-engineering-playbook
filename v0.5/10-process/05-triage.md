# 05 · Triage — keep the tracker honest

> When a new issue lands or the user asks "what should I work on?", run the triage skill.

**This stage in one breath:** Keep the tracker honest and pick the next most valuable slice. Output: one chosen slice, with the reason it won.

---

## When to run

- A new issue has been created and isn't yet labelled.
- The user asks "what next?" or "what should I pick up?".
- The tracker has unresolved `needs-triage` issues older than a few days.

## What to run

`/triage` (Matt). Drives a five-state machine plus a category tag.

**States:**

- `needs-triage` (initial)
- `needs-info` — the issue can't proceed until the human answers something
- `ready-for-agent` — an agent can pick this up unattended
- `ready-for-human` — needs human judgement or interaction
- `wontfix` — explicit decision not to do it

**Categories:**

- `bug`
- `enhancement`

## For bugs

The skill reproduces the bug first. No fix without reproduction.

## For external PRs (upstream v1.1.0)

`/triage` can treat an external pull request as an issue with attached code, run through the same state machine — gated by a per-repo toggle that `/setup-matt-pocock-skills` writes for GitHub/GitLab. The bug-only "reproduce" step generalises to **verify the claim**, and a redundancy check resolves already-implemented requests to `wontfix`. Only relevant to projects that accept outside contributions; leave the toggle off otherwise.

## For `ready-for-agent` issues

The skill writes a self-contained agent brief assuming the next agent has no context — what file to read first, what `GLOSSARY.md` terms apply, what the verification expectations are.

## Triage comments

Every triage comment is prefixed:

> *This was generated by AI during triage.*

per the skill's rule. Keeps the audit trail honest.

For an agent-owned delivery issue, mirror only durable routing facts: mission
and attempt IDs, envelope/approval/observation-contract locators, declared risk
class, maximum action, and blocking edges. Do not paste secrets, transient
`.context` paths, or a hand-carried workflow prompt. The installed
`/ai-playbook-deliver` skill remains the executable route.

## Where the output lives

In the tracker itself (Linear, GitHub Issues, etc., per `/setup-matt-pocock-skills`). No file artefacts.
